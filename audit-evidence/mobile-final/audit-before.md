Target `:5173` was the directly mounted master runtime, not checkpoint `950743c`; reference `:5174` was the clean captured master at `7155cbb`. ## Confirmed observations

1. **High — post-mount WebGL context loss leaves a black portfolio and no recovery UI.** Target: at 390px on `/projects/the-lookback`, forcing `WEBGL_lose_context` after boot left `isContextLost() === true`, the DOM title present but no visible portfolio, no alert, and A24 still visible. Evidence: `webgl-before.log`, `context-loss-before.png`. Boundaries: `src/jesper/MasterMobile.jsx` detects initialization failure but does not observe later `webglcontextlost`; captured `public/mobile-master/_nuxt/DZyj3ghP.js` owns the renderer. The standalone master uses the same rendering approach; no claim is made that this is a visual deviation from it. It is a confirmed resilience failure under the specifically requested fallback criteria.
2. **High — no WebGL provides no essential portfolio content.** Target: when `getContext('webgl2')` returns null on a direct Lookback URL, only the unavailable message is shown; no project description, media, project list or project navigation is usable, although A24 reaches idle. Evidence: `webgl-before.log`, `unavailable-before.png`; boundary: `MasterMobile.jsx` `start()`/`unavailable` branch. The reference runtime also relies on WebGL; this is a confirmed accessibility/resilience gap, not a claim of a master parity difference.
3. **Medium — renderer initialization failure leaks an uncaught Nuxt error.** Target: permit the probe context but return null to the subsequent renderer context request; the error UI and A24 appear, but Chromium logs `page: [nuxt] instance unavailable`. Evidence: `webgl-before.log`, `init-failure-before.png`. Boundary: `MasterMobile.jsx` `__masterError`/`teardown` and patched master bootstrap. This is a confirmed lifecycle defect, not a visual-comparison claim.
4. **Intentional compatibility differences, not defects:** the target moves the Featured/Full switcher 28.7–38.6px upward (dependent on width) and lifts a project Close only on dock intersection, because original master positions collide with the separately retained A24 dock. Evidence: `home-before.json` and the dock measurements; `public/mobile-master/master.css`, `MasterMobile.jsx` `clearDock`. A24 has no corresponding element in standalone master; preserving A24 is required, so reverting these positions would break interactions.

No other normal-WebGL visual or interaction discrepancy was demonstrated by these measurements. Missing original hosted media, actual video frames, high-speed transition timing, physical-device touch/scroll, real-device performance, orientation and context recovery remain unverified rather than declared matching.

## External resources and fonts

The complete list of 15 captured video URLs and individual failures is `mux-before.log`. All 15 HEAD attempts failed before an HTTP response with `curl (35) SSL_ERROR_SYSCALL` to `stream.mux.com:443`; this environment's outbound host restrictions prevent concluding anything about Mux availability for a phone. A representative image.mux.com request failed likewise. Playback, autoplay, video colours, poster transition and cropping were not verified against live media.

The captured font files in both repositories are byte-identical (SHA-256 `85b84cae419c7a78b52962e40b9e20cc082bd26c321d9e1718750f6cac3c2320`); browser font loading and sample widths including `‘`, Å/Ä/Ö, em dash and ® matched at each of six widths. The repository tree and its available history have no `sans-400`/`sans-500` glyph JSON or binary files; the captured master falls back to canvas text when they are missing, and the integrated runtime intentionally uses the same fallback. This does not verify rendering on a physical phone.
