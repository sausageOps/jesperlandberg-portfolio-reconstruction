# Mobile master-runtime migration report

## Source and changes

The source was the clean `sausageOps/httpsjesperlandberg.com` clone at `7155cbb62d4f0ea8c8be6f98c1aed4c6b1dd3d56`. It contains compiled Nuxt/Vue output, not an uncompiled component source tree. Recovery checkpoint `950743c` remains intact. The pre-existing untracked `audit-evidence/` was not changed or included in that commit.

Transferred to `public/mobile-master/_nuxt/`: `DZyj3ghP.js` (Nuxt/Vue, master renderer, Three.js, shaders and choreography); `mriNB3Nt.js` (home); `DNYapgHJ.js` (Full); `rY37MP56.js` (project); supporting `BkQn8csq.js`, `C4m1BJfK.js`, `CHzWqGxK.js`, `CSMsEA09.js`, `D6Jn8M47.js`, `DJ70QaFT.js`, `Dhdylg00.js`, `basis_transcoder.o4Hde_L7.js`, `basis_transcoder.VXdx5NbI.wasm` and the captured variable font. `face.png` was also copied. `master.css` was extracted from the captured HTML and scoped to the direct mount; `bridge.js` exposes the bundle as a browser module, and a local Nuxt manifest is provided.

`DZyj3ghP.js` was adapted at integration boundaries: auto-boot was replaced with an explicit client mount, Dato `projects`/`featured`/`site` calls use local data, browser-history writes are delegated to the host, and teardown was added for the master renderer, textures, media, ticker, resize/touch/keyboard/visibility/pointer listeners and Nuxt context. It uses the captured build's canvas-text fallback when its absent glyph files cannot be supplied. `CHzWqGxK.js` points its llama model to the existing `/assets/models/llama.glb`. The master's procedural award fallback remains unchanged. The changes are made to content-hashed captured bundle filenames, so future master updates must reapply and review these patches rather than assuming hashes describe the patched bytes.

`src/jesper/MasterMobile.jsx` mounts Vue directly into `#__nuxt` inside the React app, scopes the CSS, prepares local captured data, handles ready/error state and session cleanup, and measures the retained dock to keep the close control clear. `src/App.jsx` selects that mount only for mobile home/Full/project routes. The existing `JesperHome`, `Experience`, `Home`, `Project`, `FullIndex`, `MobileHud`, `Loader` and old shaders were **not deleted**, because they are still required by the unchanged desktop/tablet implementation. They do not mount alongside the master on a mobile portfolio route. `Hud`, `A24Nav` and their styles were not changed. The Featured/Full switcher is raised above the dock, and the project Close is raised only when it would overlap it; these intentional clearance changes differ from the standalone master.

## Routing and resources

The portfolio's existing Nuxt route transitions still drive its rendering and animation, but its history writer delegates to a host callback instead of independently writing entries. That callback makes exactly one host `pushState`/`replaceState`, maintains Vue's bookkeeping plus `jesperHomeProject` and `jesperFullOrigin`, and informs React of the route. Browser `popstate` is observed by both the host and the portfolio route view, without a second write. A24 portfolio actions go through the active portfolio route; A24 routes outside the portfolio use the existing host navigation and unmount the master. No iframe or second browsing context is used. Resizing out of phone mode also unmounts it; the canvas and WebGL context are disposed before the old desktop/tablet renderer takes over.

The adapter maps captured records from `src/jesper/data/projects.js` to the existing local image assets, including the Full catalogue, so DatoCMS does not need to be reachable. Project video URLs remain the original Mux URLs: no equivalent project videos are present in either repository and arbitrary replacement clips were not used. Mux was unreachable in this environment, so actual video decode and playback are **unverified**. The referenced master glyph JSON/bin assets are not included in the source clone; the captured master's own canvas-text fallback is used rather than inventing glyph assets. The master site's favicon/SEO service response is represented by an empty local response, not the live CMS. If WebGL2 is unavailable or its context is lost, an accessible essential-content fallback now replaces the failed canvas and keeps A24 usable. See `mobile-final-completion-report.md` for the subsequent audit, implementation, and remaining verification limits.

## Tests performed

Tests used Chromium software WebGL and local previews. Remote image/video requests were blocked unless otherwise noted. `verify/master-mobile-matrix.cjs` checked direct project routes, titles, media-slot counts, one canvas, no old mobile mount and overflow: **8/8 at each of 320, 360, 375, 390, 414 and 430px**. `verify/master-mobile-geometry.cjs` compared the project sheet, title and media geometry to the captured master: **8/8 at each width within 0.5px**. These are layout checks, not a full pixel/animation comparison.

`verify/master-mobile-full-flows.cjs` physically selected all eight projects from Full and from their restored Featured cards, then closed them and checked the centered restored card and Full-origin metadata: **8/8 at each of the six widths**. Close hit-testing against A24 was included. `verify/master-mobile-navigation.cjs` checked each project's vertical touch scroll where the content exceeded the panel, and each previous/next route via arrow keys, plus representative bidirectional horizontal touch swipes: **all eight at each width**. At 320px Casa Di Solare's media fit inside the panel, so no scrolling was expected. A separate 390px touch test confirmed a swipe beginning on the Lookback Visit link navigated to Casa Di Solare and the opposite swipe returned to Lookback.

At 390px, Full → Lookback → Close → Back → Back → Forward preserved the intended URLs and project contents. A second test covered Full → Lookback → next Book of Happiness → refresh → Close → Back; the Full-origin flag survived refresh and Book of Happiness was restored in the center. These are representative history flows, not every history permutation at every width. Instrumentation during Lookback → Book of Happiness observed both sheet DOM nodes, 15 departing items and three flights shortly after navigation, with departing items subsequently clearing. Featured selection showed a pending title becoming a title flight and then the landed title. This checks representative master choreography, not frame-by-frame parity for every case.

For colour, screenshots of Casa Di Solare and Dogelon Mars at 390px used the same locally intercepted source images on reference and target; the 280×330 middle crop had mean and maximum RGB difference 0 in each pair. This does not verify all images or remote video. At 320 and 390px, A24 dock/control geometry and menu opening matched checkpoint `950743c`; an A24 Studio navigation, return home and 390→800→390 resize showed the old and new renderers replacing each other with one canvas and no reported page errors. At 800 and 1440px, homepage/card and A24 geometry matched the checkpoint, the same old renderer remained active, and captured full-screen RGB mean difference was 0 in the measured frames; this is a representative desktop/tablet regression, not an exhaustive route/device audit.

`npm run build` passed with Vite's existing large-chunk warning. A production-preview smoke test covered home → Full → Lookback → close → Back/Forward. With WebGL disabled, the error message appeared and the A24 menu remained usable. A 390px reduced-motion smoke test opened and closed Lookback without page errors; the full reduced-motion experience was not assessed. There was no full real-device, frame-by-frame, or reachable-video verification.
